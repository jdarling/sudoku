# Commit Changes with Versioning Skill

Automates the process of versioning, updating changelog, committing changes, and creating version tags with semantic versioning (semver).

## When to Use

Invoke this skill when you need to:

- Commit completed work with a version bump
- Update VERSION constant and changelog
- Create git commits and version tags
- Prepare changes for release/push

## Workflow

### Step 1: Collect Change Details from User

Ask the user for:

1. **Change Type** (required, radio selection):
   - "Bug fix" → patch version bump (e.g., 1.2.3 → 1.2.4)
   - "New feature" → minor version bump, reset patch (e.g., 1.2.3 → 1.3.0)
   - "Breaking change" → major version bump, reset minor and patch (e.g., 1.2.3 → 2.0.0)

2. **Summary** (required, text):
   - One-line description of changes (e.g., "Added hint button", "Fixed solve button")
   - This will be used in the commit message and changelog

### Step 2: Read Current Version

1. Read `js/constants.js`
2. Extract current VERSION string (e.g., "1.2.3")
3. If VERSION not found or malformed, ask user to verify the file

### Step 3: Calculate New Version

Parse current version as semver: `MAJOR.MINOR.PATCH`

Apply bump based on change type:

- **Bug fix**: Increment PATCH only
  - 1.2.3 → 1.2.4
- **New feature**: Increment MINOR, reset PATCH to 0
  - 1.2.3 → 1.3.0
- **Breaking change**: Increment MAJOR, reset MINOR and PATCH to 0
  - 1.2.3 → 2.0.0

### Step 4: Update VERSION in `js/constants.js`

Use `replace_string_in_file` to replace:

```javascript
const VERSION = "1.2.3";
```

With:

```javascript
const VERSION = "2.0.0";
```

Include surrounding context (lines before/after) to ensure unique match.

**Error handling**: If the VERSION line can't be uniquely matched, ask user to verify the file format.

### Step 5: Update `changelog.md`

1. Read entire `changelog.md` file
2. Find the first `---` divider line after the header
3. Insert new section immediately after that divider:

```markdown
---

## [2.0.0]

- Summary text here
```

Preserve all existing changelog entries below.

**Error handling**: If changelog.md doesn't exist or can't be parsed, create it with basic structure.

### Step 6: Commit Changes

1. Stage files: `git add js/constants.js changelog.md`
2. Create commit: `git commit -m "Version 2.0.0: Summary text here"`
3. Run in terminal and check for errors
4. If commit fails, show error and suggest manual steps

### Step 7: Create Version Tag

1. Create annotated tag: `git tag -a v2.0.0 -m "Version 2.0.0: Summary text here"`
2. If tagging fails (e.g., tag already exists), show error and suggest alternatives
3. If successful, proceed to Step 8

### Step 8: Provide Push Instructions

Output final message to user:

```
✓ Version updated to 2.0.0
✓ Changelog updated
✓ Changes committed
✓ Version tag created: v2.0.0

Ready to push with:
  git push && git push --tags
```

## Error Handling Strategy

### Recoverable Errors

- **VERSION format unexpected**: Show the current file content, ask user to verify and manually update or confirm format
- **changelog.md missing**: Create with minimal structure (header + divider line) and retry
- **File replacement fails**: Show the search pattern that failed, ask user to verify file content
- **Git commit fails**: Show full error output, ask user to resolve conflicts/issues and retry

### Non-Recoverable Errors

- **Both js/constants.js and changelog.md corrupted**: Stop, ask user to repair manually
- **User cancels during questioning**: Stop gracefully
- **Filesystem permissions denied**: Stop, show error, suggest user fix permissions

## Validation

Before proceeding with git operations, verify:

1. ✓ New version string is valid semver format
2. ✓ Both files were successfully updated (read them back to confirm)
3. ✓ Git staging will work (check `git status` to see staged files)

## Example Execution

**User request**: "commit the theme picker feature"

**Agent questions**:

```
What type of change?
○ Bug fix
○ New feature ← selected
○ Breaking change

Summary of changes:
> Add theme picker UI with Dark and Default themes
```

**Agent process**:

1. Read current VERSION from js/constants.js → "1.10.1"
2. Parse semver → major=1, minor=10, patch=1
3. Apply minor bump → "1.11.0"
4. Update js/constants.js: VERSION = "1.11.0"
5. Update changelog.md with new section for [1.11.0]
6. Commit: `git commit -m "Version 1.11.0: Add theme picker UI with Dark and Default themes"`
7. Tag: `git tag -a v1.11.0 -m "Version 1.11.0: Add theme picker UI with Dark and Default themes"`
8. Output success message with push instructions
